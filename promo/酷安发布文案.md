标题：

【开源】旋律 MelodyPlayer：本地优先的 Android 播放器，无广告 · 无账号 · 不上报数据


正文：

一句话先说清楚

旋律（MelodyPlayer）是一款**本地优先**的 Android 音乐播放器，用 Kotlin + Jetpack Compose + Media3 写成，
MIT 协议完整开源。它没有账号体系，没有广告，没有统计 SDK，安装包 8.5 MB，APK 内部不含任何原生库。
联网只发生在你亲手点下「联网获取歌词 / 封面」的那一次。

它是自用工具，不是商业产品 —— 没有会员、没有启动页、没有推荐流，也没有任何想要从你身上拿走的东西。


为什么要为「本地音乐」单独写一个播放器

如果你和我一样，曲库是这些年一点点攒下来的本地文件，大概会遇到同一个处境：
现在的主流播放器都是以在线曲库为主体重构过的，本地音乐被降级成一个"更多"里的入口。

具体一点的麻烦事：

· 扫描出来的本地曲库和在线曲库混在一起，找一首自己的歌要绕好几层
· 歌词只对自家曲库生效，本地文件的内嵌歌词、同目录的 .lrc 一律读不到
· 专辑封面缺失时基本没有补救手段，一整屏灰色占位
· 开屏广告、首页推荐、后台常驻，一个只是"想听自己存的歌"的需求，被塞进了一整套运营体系

这些都不算大问题，但每一件都要绕一下，绕久了就想自己写一个。
旋律就是按"本地音乐应该被当成一等公民"这个前提从头做的。


功能

播放

· Media3（ExoPlayer）作为播放内核，MediaSessionService 托管后台播放
· 通知栏 / 锁屏媒体卡片：封面、歌名、播放暂停、上下首，耳机按键可用
· 四种播放模式由一个按钮循环切换：顺序播放 → 列表循环 → 单曲循环 → 随机播放
  早期版本是「随机开关 + 循环开关」两枚独立开关，能组合出「随机 + 单曲循环」这种自相矛盾的状态，
  现在合成一个枚举，图标即状态，不存在"看起来开着其实没生效"的组合
· 全屏播放页支持上下滑动切歌，不想用可以在设置里关掉（它和歌词滚动会抢手势，所以给了开关）
· 播放队列可重排：队列页任意一行都能上移 / 下移，改完立即生效
· 迷你播放条常驻底部，点击展开全屏


曲库

· 扫描设备音频（MediaStore），也可以从文件选择器导入外部文件（SAF）
· **只扫描指定文件夹**：打开后不再读取整机媒体库，只扫你授权的那一个目录（连子目录一起），
  因此也不再需要「音乐和音频」权限 —— 只有这一个目录的读取权
· **自定义歌单**：新建 / 重命名 / 删除，任意曲目可加入，歌单内可上移下移，
  **歌单顺序即播放顺序**。从歌单移除只动歌单，曲库里那首还在
  （顺手修了一个自己埋的坑：归档会把曲目的内部标识从 ms:<id> 换成 lib:<文件名>，
  歌单里存的正是这个标识，不跟着换的话歌会在歌单里静悄悄消失）
· **批量选择**：**长按任意一行**进入多选（已在多选态时长按 = 再勾/取消这一首），之后可以批量加入歌单、从歌单移除、去掉封面、隐藏、把歌词与封面嵌入文件。
  多选态下按返回键只退出多选，不会退出 App。
  顶上有已选几首与全选；歌单视图里「加入歌单」自动换成「从这个歌单移除」
  —— 已经在歌单里还问"要不要加"，是句废话
  批量最怕的是"部分成功却只报一句『完成』"，所以这里一定说清没做成的部分：
  选了 10 首只有 3 首是新的，会明确告诉你「已加入歌单 3 首；原本就那样 7 首」
  另外「去掉封面」只删 App 这一层（联网缓存的 + 相册自定义的），随后退回文件里内嵌的那张 ——
  想连内嵌封面一起换掉就用「嵌入标签 → 写入封面」，那是直接改文件
  选中项跟着视图走：切歌单、搜索收窄、批量操作之后都会自动收敛，
  不会出现"已选 5 首"里混着列表上根本看不见的歌
· 搜索、按多种字段排序
· 隐藏曲目：不想要的从列表里拿掉，随时可恢复，不动文件本身
· 归档：把曲目复制进 App 专属目录统一管理，副本落地后原曲自动让位，不会留下空库
· 编辑歌曲信息（歌名 / 歌手 / 专辑）—— 改动只作用于 App 内视图，不写回原文件


歌词（这一块是重点）

支持五类来源：

1. 内嵌时间戳歌词 —— ID3v2 的 SYLT / USLT、FLAC 的 LYRICS 字段，有时间轴就精确同步
2. 内嵌纯文本歌词 —— 没有时间轴时，按歌曲时长自动均分对齐
3. 同名 .lrc 文件 —— 音频旁边放一个同名的就行
4. 手动导入 .lrc
5. 联网获取 —— 两个来源：网易云（按歌名 + 歌手检索，可选官方翻译合成双语）、LRCLIB（按歌名 + 歌手 + 时长签名匹配）

两个联网来源可以在设置里**分别开关**，两家都关掉时会明确提示，而不是静默地什么都搜不到。

当前歌词来自哪里，可以到「设置 → 歌词 → 当前曲目歌词来源」看（连同步状态一起：精确同步 / 自动对齐）；
点「联网获取歌词」挑候选时，每一行也会标出是哪家给的。

另有一个我觉得很实用的点：**歌词和封面都能写回音频文件标签**（ID3v2 / FLAC）。
写回去之后，这些东西就跟着文件走了 —— 换任何播放器、拷到任何设备都还在，不再依赖某个 App 的私有缓存。
入口在多选之后的「嵌入标签」，可以只写歌词、只写封面、或者两样一起。

几个如实说明的点：
  音频数据原样保留，不转码、不重新压缩，只重写文件头部的标签区
  只支持 MP3 与 FLAC；M4A / Ogg / WAV 会明确告诉你"这个格式写不了"，不会默默失败
  改文件不可撤销，所以确认按钮要点两次（先「下一步」，再「确认修改文件」）
  写入时保留原标签里的其他帧，已有歌词帧是替换而不是叠加
  汇报按「写成功 / 格式不支持 / 没写入权限 / 写失败 / 没有内容可写」分开说


专辑封面

· 优先使用音频文件的内嵌封面（ID3v2 的 APIC / PIC、FLAC 的 PICTURE 块，自研解析）
· 内嵌没有时，走 iTunes Search API 联网匹配，命中即缓存到本地
· 搜索行为可配置：**地区链**（默认 中国台湾 → 中国香港 → 美国，最多可选 4 个）、**匹配评分下限**（20 – 170，默认 90）
  说明一下为什么默认列表里没有中国大陆区：iTunes 中国区对本地曲目的匹配质量明显更差，命中率低，所以默认链路里不带它，需要的话可以自己加。
· 批量补封面时给的是**确定式进度**：第 N / 总数 + 当前阶段（搜索候选 / 下载封面 / 写入缓存）+ 成功 · 无匹配 · 失败三类计数。
  不是那种转圈转到底、不知道卡在哪一步的滚动条。


KWM 音乐解密

酷我客户端的加密文件（.kwm）可以直接导入：App 在本地解密之后**按原格式**归档进曲库，不重新编码。
也就是说原文件是 MP3 就还是 MP3，是 FLAC 就还是 FLAC，不会为了"统一格式"再压一遍、把音质再削一层。


外观

· 四套主题色：靛蓝 / 青绿 / 玫红 / 琥珀
· 封面形状可选（圆角方形 / 圆形）
· 歌词字号四档，行高与行距同步缩放（只放大字号、行高不动的话，大号歌词会挤成一坨）
· Android 12 及以上支持真实毛玻璃（RenderEffect），低版本自动退化为半透明，不做假毛玻璃


技术实现（给同样写 Android 的朋友）

选型

· 语言 / UI：Kotlin，Jetpack Compose（Material 3）
· 播放：Media3 1.8.0（ExoPlayer + MediaSession）
· 异步：Coroutines / Flow
· 存储：SharedPreferences + 内部目录文件索引
· 构建：Gradle 8.9 + AGP 8.7.3，compileSdk 36 / minSdk 26（Android 8.0）/ targetSdk 36

依赖是刻意压到极短的，算上 Compose BOM 一共 15 条。具体做法：

· 标签解析：自研 ID3v2 / FLAC 解析与写入，没有引第三方标签库
· JSON：自研极简解析器，没有引 Gson / Moshi
· 网络：标准 HttpURLConnection 封装，没有引 OkHttp / Retrofit
· 图标：全部手写 ImageVector，没有引图标库

代价是解析器要自己处理各种边界（编码、非标准标签、截断文件），
收益是 APK 里没有任何一行不是自己写的代码 —— 出了问题能直接定位到源码，而不是先猜是哪层库在做事。

没有任何原生代码

工程里没有 C / C++，也没有任何自带的 .so，只保留 abiFilters 用于过滤依赖里带进来的那一个图形库。
这也是 APK 能做到 8.5 MB 的原因之一：没有多 ABI 的 native 库要打三份。

测试

core/ 与 data/ 两层不依赖 Compose，纯逻辑可以在 JVM 单测里直接跑，目前 **305 条单测**，
覆盖 LRC 解析、标签读写、KWM 解码、歌词匹配、封面匹配打分、歌单增删改排、批量操作分组汇报、限定文件夹的文件判定、曲库查询与隐藏 / 归档规则等。
把逻辑和 UI 分开，最大的好处是改播放链路的时候不用把 App 装到手机上一条条点。


权限与隐私

这是我最想单独说的一段。

申请的权限一共 8 项，全部列在这里：

· 读取音频文件（Android 13+ 用 READ_MEDIA_AUDIO，旧版本回退 READ_EXTERNAL_STORAGE）
· 发布通知（POST_NOTIFICATIONS）
· 保持唤醒（WAKE_LOCK）
· 前台服务 + 前台服务（媒体播放）—— 后台播放必需
· 网络访问 + 网络状态

没有的：定位、通讯录、电话状态、相机、麦克风、读取应用列表，一个都没有。

关于数据：

· 不收集、不上报任何数据。没有统计 SDK，没有崩溃上报，没有账号体系
· 联网只在你主动触发时发生：获取歌词、获取封面、获取翻译
· 请求直接发往对应服务，只带检索用的歌名 / 歌手 / 时长，不上传任何本地文件
· 曲库索引、歌词、封面缓存全部在本机，卸载即清除
· 没有云端，也就没有"换个手机登录一下"；这是取舍，不是待办


已知限制（写在前面，省得你装完才发现）

· 只编译了 arm64-v8a / armeabi-v7a 两种 ABI，x86 模拟器需要自己加 abiFilters 重新编译
· 发版没有开启代码混淆，便于排查问题，代价是包体不是最优、反编译门槛低
· 顺序播放在底层映射为 REPEAT_MODE_ALL —— 这是为了绕开「队列走到最后一首时系统撤掉下一首按钮」的坑，
  代价是顺序播完一圈会从头继续，它和列表循环的差别目前只剩界面图标
· 歌单只存曲目标识、不存歌曲快照：文件被删或被移出 App 库后，歌单里那一项会直接消失
  （歌单页会提示有几首已不在曲库），不会留一条点不开的记录
· 「只扫描指定文件夹」依赖系统目录树递归枚举，少数深度过深或提供器特殊的目录可能扫不全
· 没做平板 / 横屏专门适配
· 纯本地定位：不做在线曲库、不做流媒体、不做账号同步

  标签解析器只抽歌词，APIC / PIC / PICTURE 一个都没解，界面上永远退回占位图。
  现在自己解析这三种封面帧并按字节缓存（滚动列表不卡），"去掉封面"之后也能真的退回内嵌那张
· 新增：设置页「关于」加**开源地址**与**QQ 群 1106718126**入口，没装 QQ 自动复制群号

  原因是去封面只在"当前播放的那首被去掉"时才发刷新信号，批量去掉别的歌时那些行压根不重组，
  继续画着内存里的旧图；现在无条件通知
· 修复：写入封面后内嵌封面缓存没失效，会出现"提示写成功了，封面却没变"

· 修复：**长按歌曲不进入多选**。行点击用的是 clickable，它根本没有长按回调，
  多选入口只能塞在 ⋮ 菜单里，等于让用户先想"多选在哪"；现在改成 combinedClickable，
  长按任意一行直接进多选并选中它（已在多选态时长按 = 再勾/取消这一首）
· 修复：**多选态按返回键直接退出 App**。返回键只挂了播放页一个 BackHandler，
  多选不算"一层界面"，系统就当没得关、走了默认退出；现在多选也接管返回
  （播放页全屏时仍优先关播放页，不打架）
· 修复：切到队列 / 设置页后多选状态残留，"已选 N 首"跟着跑到别的标签页，现在切标签就清掉

【开源】旋律 MelodyPlayer —— 本地优先的 Android 音乐播放器

Kotlin + Compose + Media3，MIT 开源，自用工具。

· 无账号、无广告、无统计 SDK，联网只在你主动点「获取歌词 / 封面」时发生
· 8 项权限，没有定位 / 通讯录 / 读取应用列表
  申请的是：读取音频、通知、保持唤醒、前台服务、网络
  （开了「只扫描指定文件夹」就连读取音频都不用了，只持有那一个目录的读权）
· 8.5 MB，工程内没有任何原生代码，也没有自带的 .so
· 自定义歌单：歌单顺序即播放顺序，歌单内可上移下移；播放队列同样可重排
· 批量选择：批量加歌单 / 移出歌单 / 去掉封面 / 隐藏 / 嵌入标签，汇报一定说清哪几首没动成
  （「去掉封面」只删 App 存的与相册自定义的，随后退回文件内嵌的那张）
· 歌词五个来源：内嵌时间戳 / 内嵌纯文本 / 同名 .lrc / 手动导入 / 联网（网易云 + LRCLIB 可分别开关），
  来源可在设置里查到；歌词可以写回音频标签，换播放器也带着走
· 封面：内嵌优先，缺失时走 iTunes 匹配，地区链与评分下限可自定义，带确定式进度
· KWM 解密：酷我加密文件本地解密后按**原格式**归档，不二次编码
· 305 条单测，依赖 15 条，标签 / JSON / 网络 / 图标全部自研
· Android 8.0+，arm64-v8a / armeabi-v7a

下载：https://github.com/1kui/MelodyPlayer/releases/latest
开源：https://github.com/1kui/MelodyPlayer

第三部分 · 配图建议
====================================================================

文章里插图的顺序建议按"第一眼能看出这是什么"来排，别把设置页放最前面：

1. 封面：全屏播放页 —— 展示封面 + 进度条 + 播放控件，最能说明"这是个播放器"
2. 歌词页 —— 展示逐行高亮
3. 曲库页 —— 顶部这版的歌单胶囊行是新的，优先给它一张；再配一张搜索 / 排序
4. **多选状态下的曲库页** —— 复选框 + 底部批量操作条，这版最想让人看到的东西
5. 设置页 —— 展示「只扫描指定文件夹」、歌词来源开关、封面地区与评分、主题色等可配置项
6. （可选）迷你播放条 + 通知栏媒体卡片

如果要在文章顶部放一张横版主图，建议用品牌渐变（#00C2FF → #2563FF → #7C3AED）
配一句定位语，比如"把你自己的音乐，放回播放器的主角位置"。

第四部分 · 发布前自查清单
====================================================================

发送之前建议过一遍这几条，都是酷安上容易被追问的点：

[ ] 标题里带不带"开源"？带了会有一批人是奔着源码点进来的，正文里要能立刻找到仓库地址
[ ] 下载链接是直链还是跳 GitHub？酷安外链点击率一般，Release 页地址要放在正文靠前的位置
[ ] 版本号与 APK 大小是否与正文一致（当前 v2.11 / 8.6 MB）
[ ] 权限清单是否与系统实际请求的一致 —— 别写"只要三个权限"然后被截图打脸
    （注意：开了「只扫描指定文件夹」之后读取音频权限是可以不给的，别把两套清单混着说）
[ ] 是否明确写了"自用工具、不承诺商业级维护"？写清楚能挡掉一半"为什么不做 XX 功能"的追问
[ ] 免责声明是否保留，尤其是 KWM 与第三方接口那两条
[ ] 截图里有没有出现真实歌曲名 / 私人曲库内容？建议用示例库截图，避免不必要的麻烦
[ ] 回复预期准备：ABI 是否支持 x86、会不会做流媒体、能不能同步歌词到云端、
    为什么顺序播放和列表循环看起来一样、歌单会不会同步到云端 —— 这几条大概率会被问到
