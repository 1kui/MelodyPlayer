# 旋律 · MelodyPlayer

一个纯本地优先的 Android 音乐播放器。Kotlin + Jetpack Compose + Media3 写的，没有账号、没有广告、没有后台统计，联网只发生在你主动点击「联网获取歌词 / 封面」的时候。

## 功能

### 播放

- Media3（ExoPlayer）播放内核，`MediaSessionService` 托管后台播放
- 通知栏 / 锁屏媒体卡片：封面、歌名、播放暂停、上下首
- 四种播放模式由**一个按钮循环切换**：顺序播放 → 列表循环 → 单曲循环 → 随机播放（不拆成「随机开关 + 循环开关」两枚开关——那样能组合出「随机 + 单曲循环」这种自相矛盾的状态）
- 全屏播放页支持**上下滑动切歌**（可在设置里关闭）
- 迷你播放条常驻底部，点开进全屏
- **播放队列可重排**：队列页**长按任意一首，直接拖到想要的位置**（不是一格一格挪），松手生效；
  拖动中被拖行浮起、其余行让位并压暗，落点一目了然，拖到列表上下边缘会自动滚动
  （自动滚动的下边界按**看得见的底边**算，手指停在底栏上方就会开始滚，
  不必把它拖到底栏下面去；拖动全程列表自己的滚动是关掉的，行不会和手指错位）
  （菜单里的「上移 / 下移」也还在，两者改的是同一条队列）
- **播放速度**：六挡预设 `0.75× / 0.9× / 1× / 1.1× / 1.25× / 1.5×`，变速**不变调**；
  非原速时播放页信息行上挂一个 `1.25×` 的小标（原速什么都不画 —— 一个永远写着 `1.00×` 的角标只是噪音）
  - 上限刻意只到 1.5×：再快就只能听个响，而这个 App 里没有播客/有声书的章节概念，不需要为赶进度存在的挡位
  - 跨过 1.0 时会**吸附到正好 1.0**：从 1.0 起步一路减是 1.0 → 0.9 → …，不吸附的话很难"刚好回到原速"
- **睡眠定时**：五挡预设 `15 / 30 / 45 分钟 · 1 / 1.5 小时`，另有「自定义时长…」可以自己填分钟数（1–600）
  - 自定义的输入框只认数字、只在 1–600 之间放行：填 `0` 或 `601` 会把「开始计时」置灰并说明范围，
    而不是偷偷夹到边界 —— 夹取等于在点确定的那一刻发生一次看不见的修改
  - 倒计时画在播放页的 `29:59` 小标上，不足一分钟时改成一句人话
  - 到点**只暂停、不停服务**：通知、队列与播放位置全部留着，睁眼一键就能续播
  - 计时跑在**播放服务**里、用开机以来的单调时钟：划掉任务卡片也照常生效，
    改系统时间 / 时区 / 夏令时都不会让一个「还有 20 分钟」的定时瞬间到期
  - 只存内存、**不落盘**：重开 App 后定时器自然失效，否则会变成"重开 App 五分钟后莫名暂停"

### 曲库

- 扫描设备音频（MediaStore），另支持 SAF 导入外部文件
- **只扫描指定文件夹**：打开后不再读取整机媒体库，只扫你授权的那一个目录（连子目录一起），因此也就不再需要「音乐和音频」权限
- **自定义歌单**：新建 / 重命名 / 删除，任意曲目可加入；歌单内可上移下移调整顺序，**歌单顺序即播放顺序**
  - 曲库首屏就是**一排横滑歌单卡**（封面＝歌单里第一首的封面），首张固定是「全部歌曲」
    —— 它就是原来那颗「全部」胶囊，也是"默认歌单"这个位置；末尾一张是「新建歌单」
  - 歌单卡只有一排，顶上不再叠"歌单胶囊 + 维度分段 + 榜单胶囊"三层选择器：
    三层各用不同的控件形态和边距，凑在一起就是"排版错位"的来源，第一屏也几乎全被导航占满
- **批量选择**：**长按任意一行**进入多选（已在多选态时长按 = 再勾/取消这一首），之后可批量 **加入歌单 / 从歌单移除 / 去掉封面 / 隐藏 / 嵌入标签**；
  顶部显示已选几首与全选，歌单视图下「加入歌单」自动换成「从这个歌单移除」
  - 多选态下按返回键只退出多选，不会顺手把播放页关掉、更不会直接退出 App
  - 汇报一定说清**没做成的部分**：选了 10 首只有 3 首是新的，会明确告诉你「原本就那样 7 首」
  - **去掉封面只删 App 这一层**（联网缓存的与相册自定义的），随后**退回文件里内嵌的那张**；
    想连内嵌封面一起换掉就用「嵌入标签 → 写入封面」，那是直接改文件
  - 选中项跟着视图走：切歌单、搜索收窄、批量操作后都会自动收敛，不会留下"看不见却还选着"的歌
- **三种浏览维度**：右上角 ⋮ →「浏览方式」（按歌曲列表 / 按专辑 / 按歌手）
  - 它原来占据首屏一整行 —— 而首屏是该用来放歌的，所以搬进了菜单。
    进去之后列表顶部会出现一条「按专辑浏览 · 12 张 + 返回歌曲列表」，**退出的路写在屏幕上**，
    不用回头去翻菜单
  - **专辑**：两列封面网格，封面缺失时用现成的程序化占位图（按标题+歌手算的稳定色调，不需要占位图资源）。
    点进专辑页 = 头部 + 曲目列表 +「整张连播 / 加入队列」；歌手页同理
  - 分组键是 `(专辑名, 歌手)` 而不是只按专辑名 —— "Greatest Hits" 满天飞，只按专辑名合并的话点进去作者都换了人。
    代价是**合辑会被拆开**（同一张合辑里每首歌的 artist 不同），这是一处**已知的降级**
  - 没填专辑或歌手的会归一成「未知专辑 / 未知歌手」并沉到列表最后；但它们**不会跨歌手合并**，
    否则一个「未知专辑」卡片里会装着几十个互不相干的作者
  - 歌单视图里不给维度切换：歌单是"我挑出来的这几首"，再按专辑拆一遍，用户手排的顺序就没了
  - 切维度会清掉多选：底部那条"已选 N 首"此时指的是屏幕上一个也看不见的歌
- 搜索、按多种字段排序；**命中的关键字在标题与「歌手 · 专辑」两行里加粗标出**，
  一眼能看出是标题匹配上还是歌手匹配上
- **最近搜索**：搜索框空着时铺一行「最近搜索」词条（最多 8 条），点一下直接搜、右侧小叉单独删、也可以一次清空
  - 只在**真的搜过一次**之后才写入：键盘上的搜索键，或者**关掉搜索框**那一刻
    （后者才是多数人的习惯——一路打字就存会堆出"晴""晴天""晴天 "一串半成品）
  - 去重不分大小写，但保留最后一次输入的大小写
- **最近常听**：入口在**播放队列页顶栏**的历史图标里，弹层里是一列按播放次数排好的曲目
  - 它原来是曲库首屏的一排横滑卡，和歌单卡、维度切换一起抢第一屏；曲库腾给歌单之后搬到「播放」这一栏
    —— 那一栏本来就是回答"我在听什么、听过什么"的地方
  - 这里原来还有一份「最近播放」，两榜用一个胶囊切换。撤掉它是因为**两个榜单回答的其实是同一个问题**
    （"我想不起歌名，但我知道听的是哪首"），而列表常常高度重叠，用户每次点开都要先做一次"该翻哪一个"的选择。
    留「最常听」是因为它**搜索与翻列表都替代不了**：最近听的那几首还在通知栏和迷你条上找得到，
    而"我反复听的是哪几首"只有这份榜单记得住
  - 弹层而不是塞进队列列表里：队列那个列表上挂着长按拖动排序的手势，往里面加一段不可拖的曲目区，
    在那一段上长按会触发拖动识别器而手指下面没有队列行，表现为"长按了、什么都没发生"
  - 点一行就是**从那一首开始放**整批（这个榜单当队列），底部「播放全部」同一件事
  - **听满 30 秒才记一笔** —— 否则一路快切会把整张曲库刷成"常听"，这份榜单第二天就没法看了
  - 记录里存了标题/歌手快照：文件删了之后榜单上那条还看得见；曲库里一首都找不到时
    会如实说明"还没听满 30 秒"，而不是留一片空白
- **隐藏曲目**：不想要的歌从列表里拿掉，可随时恢复
- **归档**：把曲目复制进 App 专属目录统一管理（副本到手后原曲自动让位，不会留空库）
- 编辑歌曲信息（歌名 / 歌手 / 专辑），改动只作用于 App 内视图，不动原文件

### 菜单与确认

针对单首歌的操作，点右侧 ⋮ 之后从**底部弹窗**展开，不再是贴边的一长串小下拉框：

- **按对象分组**（播放 / 歌单 / 歌曲信息 / 曲库管理），顶部先摆出这首歌的封面、歌名与歌手 —— 打开就知道自己在给谁操作
- **列表页只留"跟这个列表有关"的动作**：播放、放进哪个歌单、排歌单顺序、改显示信息、归档 / 隐藏 / 移出。
  改**这首歌本身**的那些（换封面、写标签、歌词副本）统一在**播放页的 ⋮** 里 ——
  那儿弹层的抬头就是这一首的封面与歌名，做这些事时看得见对象；列表页一行也挂着同一份，
  结果是同一个功能两个入口、两处文案，菜单还长到要滑一段才读完
- 每一项**带一句说明**，把后果讲明白：「隐藏这首 → 设置页随时能恢复，文件不受影响」「归档到 App 库 → 原文件删了也不会丢」
- 会**丢东西**的动作（取消归档 / 移出列表）才标红，其余不标 —— 标红是一项承诺：做了就回不来
- 同一句文案不跨页面复用：曲库里的「移出列表」到队列里是「移出队列」，队列里也不再出现毫无意义的「下一首播放」
- 「清空播放队列」这种一颗图标就能把正在听的歌停掉的操作，一律先弹确认

### 歌词

支持多种来源：

| 来源 | 说明 |
| --- | --- |
| 内嵌时间戳歌词 | ID3v2 `SYLT` / `USLT`、FLAC `LYRICS`，带时间轴则精确同步 |
| 内嵌纯文本 | 无时间轴时按歌曲时长自动均分对齐 |
| 同名 `.lrc` | 音频旁边放同名歌词文件即可 |
| 手动导入 | 从文件选择器导入 `.lrc` |
| **网易云** | 按歌名 + 歌手搜索，可选官方翻译合成双语 |
| **LRCLIB** | 按歌名 + 歌手 + 时长签名匹配 |

- 两个联网来源都可以在设置里**分别开关**
- 当前歌词的来源可以在**设置 → 歌词 → 当前曲目歌词来源**里看到（含同步状态：精确同步 / 自动对齐）；点「联网获取歌词」选候选时，每一行也会标出是哪家给的
- 歌词可**写回音频文件标签**（ID3v2 / FLAC），换播放器也带着走
- **歌词偏移**：整首歌的时间轴差半秒，不用去改文件 —— 播放页 **⋮ →「歌词偏移」**
  里有「提前 0.5 秒 / 延后 0.5 秒 / 恢复未校正」三项，范围 ±30 秒。
  当前值写在第一项的副标题上（`当前：延后 0.5 秒`），点完**不关弹层**，
  可以连着按几下直到对上 —— 偏移是这个菜单里唯一"要连按"的动作，
  关一次开一次等于调一挡就要重进一次菜单
  - 它原来在歌词区顶上是一条 `− 未校正 ＋` 的小条（v2.19–v2.20），撤掉是因为那一行
    占的是歌词正文的位置，而歌词页每一行的高度、以及"当前行停在视口 1/3 处"的对照关系
    都跟着它变；功能本身一挡没少
  - 偏移**存在 App 里、按曲目独立**（含未校正状态一起记），所以不会"调了一首，别的歌也跟着歪"
  - 偏移**只影响显示与对齐，不写回文件**：写回文件的一定是原始时间轴，
    别的播放器读到的不会被这里的校正污染
- **歌词副本管理**：联网获取 / 导入的歌词会落在 App 内部目录（不碰原文件）。副本认的是**歌曲**而不是目录，
  所以入口长在能看到那首歌的地方，而不是设置页里一份按全库列出的清单：
  **播放页 ⋮**（正在播的这首）· **多选底部**（选中的那几首）· **设置 → 歌词**（全库口径）
  - 弹层里按歌分组：组头是歌名 + `N 份 · 多大 · 最近一次什么时候存的`，
    组内每一份可以点开看正文、右侧垃圾桶删掉这一份；两份以上时组头出现「全部删除」，
    底部则给出「删除以上全部副本（N 份）」
  - 副标题会点明「含 M 份自动匹配缓存」：那一份删了还会被再取回来，和用户**选定**的那份不是一回事
  - 认不回歌曲的**孤儿副本**（歌词索引丢了）排在最后、组头写明「只能删」，
    底部另有「清理未关联副本（N 份）」—— 它与「删除以上全部」是两个量级，所以各自写明删多少份
  - 设置页「歌词 → 歌词副本」那个入口是**全库**口径：列的是磁盘上所有副本，
    副标题写成`N 首歌 · 共 M 份 · 其中 K 份认不回歌曲`（那里没有"选"这个动作，不会照抄"已选 N 首"）

### 嵌入标签（把 App 里的东西写进音频文件）

**两个入口，都不需要先长按进多选**：

| 入口 | 作用范围 |
| --- | --- |
| 播放页 → ⋮ →「写入文件标签…」 | 正在播放的这一首 |
| 长按进多选 → 底部「写进文件」 | 选中的那几首 |

（v2.21 撤掉了「某一行 ⋮」与「右上角 ⋮」两个入口：写标签改的是歌本身，
归到播放页的 ⋮（单曲）与多选批量条（一批）；要对当前列表整批写，多选里全选即可。）

弹的是同一个勾选框，可以勾选要写什么：

| 写什么 | 落到哪 |
| --- | --- |
| 歌词 | MP3 的 ID3v2 `USLT`、FLAC 的 Vorbis Comment `LYRICS` |
| 封面 | MP3 的 `APIC`、FLAC 的 `PICTURE` 块 |

- 音频数据**原样保留**，不转码、不重新压缩；只重写文件头部的标签区
- **只支持 MP3 与 FLAC**，M4A / Ogg / WAV 会明确告诉你"这个格式写不了"，而不是默默失败
- 改文件不可撤销，所以确认按钮要点两次（先「下一步」再「确认修改文件」）
- 写入时保留原标签里的其他帧（ReplayGain、多语言标题之类），已有歌词帧会被替换而不是叠加
- 汇报按「写成功 / 格式不支持 / 没写入权限 / 写失败 / 没有内容可写」分开说，
  不会只丢一句"已完成"让你以为全都进去了

### 专辑封面

三级来源，顺序固定：**App 缓存 → 文件内嵌封面 → 渐变占位图**

- **文件内嵌封面**：ID3v2 `APIC` / `PIC`、FLAC `PICTURE` 块，自己解析字节
  （缓存按字节存而不是按位图存，一首歌只解一次，滚动列表不会卡）
- App 这层没有（也没联网匹配上）时才走 **iTunes Search API**，命中即缓存
- 可配置：**搜索地区链**（默认 中国台湾 → 中国香港 → 美国，最多选 4 个）、**匹配评分下限**（20–170，默认 90）
- 打开「自定义获取地区」就**自动实测一遍各地区延迟**（单位 ms，每测一个刷新一个），
  也可以随时「重新测速」：连不上、超时或被接口限流时如实显示**无法连接**，不拿一个假数字糊弄。
  延迟是当下网络状况，只留在内存里、不落盘 —— 存下来只会让人对着过期的数字做决定
- 批量补封面时显示**确定式进度**：第 N / 总数 + 当前阶段（搜索候选 / 下载封面 / 写入缓存）+ 成功·无匹配·失败计数
- 「去掉封面」删的是 App 这一层，之后会退回文件内嵌的那张 —— 它的实现就是上面这条解析
- **重新解析内嵌封面**：在别的播放器或工具里换过封面图时，缓存里那份已经过期，
  不给一条显式重读的入口就只能靠重启 App。三处都能点 ——
  播放页 → ⋮ →「重新解析内嵌封面」（正在播的这首）、
  多选底部的「重读内嵌封面」（选中那几首）、设置 →「专辑封面 → 重新解析内嵌封面」（整库）。
  整库那条扫完会告诉你**有几首真的带封面**，因为"扫完了"本身回答不了"换成功没有"

### KWM 音乐解密

酷我客户端的加密文件（`.kwm`）可以直接导入：App 在本地解密后按**原格式**归档进曲库，不重新编码。

设置页有「KWM 音乐解密」分组，说明解密原理、扫描位置与文件命名规则。

### 外观

- 主题色可选（多种强调色）
- 封面形状可选（**圆角方形 / 圆形**）
- 歌词字号四档，行高与行距一起缩放
- Android 12+ 上支持真实毛玻璃（`RenderEffect`），低版本自动退化为半透明

### 设置页

设置页现在是**二级页**结构：首屏只摆「常改的」与几个分组入口，点进去才是详细项。

| 分组 | 里面有什么 |
| --- | --- |
| 常用（首屏直接展开） | 播放模式 · 上下滑动切换歌曲 · 睡眠定时 |
| 曲库与文件 | 曲库（扫描范围 / 重新扫描） · App 音乐库（归档） · 已隐藏的曲目 |
| 播放与外观 | 播放（播放模式 / 滑动切歌 / 睡眠定时） · 外观 · 歌词（来源开关 / 歌词副本 / 写回文件） |
| 在线内容 | 专辑封面（地区链 / 匹配评分下限 / 重新解析内嵌封面） |
| 高级 | KWM 音乐解密 |
| 关于 | 版本 · 加入 QQ 群 · 开源仓库 |

- 二级页顶栏左侧是**返回箭头**（不是「设置」标题旁的箭头），返回键与它行为一致
- 首屏每个入口卡带一句当前状态摘要（「已隐藏的曲目 · 12 首不参与列表与搜索」），
  让"我到底要不要进去"变成一眼能答的问题，而不是"进去看看有没有"
- 首屏的「常用」三项在「播放」二级页里也有一份，这是故意的：首屏那份是快捷方式（省一次点击），
  二级页那份带完整说明；两边读写同一个状态，不会出现"这一处改了、那一处没变"

「关于」里有**开源地址**（<https://github.com/1kui/MelodyPlayer>，MIT 协议，欢迎提 Issue）和
**QQ 群 1106718126** 的入口——没装 QQ 时会自动把群号复制到剪贴板，不会点了没反应。

## 数据与隐私

- **不收集、不上报任何数据**，没有统计 SDK、没有崩溃上报、没有账号体系
- 联网只发生在你**主动触发**时：获取歌词、获取封面、获取翻译
- 请求直接发往对应服务：网易云音乐、[LRCLIB](https://lrclib.net)、iTunes Search API
- 全库扫描、歌词、封面缓存都在本机，卸载即清除
- 需要的权限：读取音频（`READ_MEDIA_AUDIO`）、前台服务（播放）、通知
- 开启「只扫描指定文件夹」后不再需要 `READ_MEDIA_AUDIO`，只持有你授权的那一个目录的读取权

## 已知限制

- 只做了真机在用的两种 ABI（`arm64-v8a` / `armeabi-v7a`），x86 模拟器需要自行加 `abiFilters`
- 发版未开启代码混淆（`isMinifyEnabled = false`），便于排查问题
- 顺序播放在底层映射为 `REPEAT_MODE_ALL`——这是为了绕开「队列走到最后一首时系统撤掉下一首按钮」的坑，代价是顺序播放放完一圈会从头继续，与列表循环的差别只剩界面图标
- 歌单只存曲目 key，不存快照：文件被删或被移出 App 库后，歌单里那一项会直接消失（歌单页会提示有几首已不在曲库），不会留一条点不开的记录
- 「只扫描指定文件夹」依赖 SAF 目录树递归枚举，少量深度过深或提供器特殊的目录可能扫不全
- 未做平板 / 横屏专门适配
