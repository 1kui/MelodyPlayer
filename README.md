# 旋律 · MelodyPlayer

一个纯本地优先的 Android 音乐播放器。Kotlin + Jetpack Compose + Media3 写的，没有账号、没有广告、没有后台统计，联网只发生在你主动点击「联网获取歌词 / 封面」的时候。

## 功能

### 播放

- Media3（ExoPlayer）播放内核，`MediaSessionService` 托管后台播放
- 通知栏 / 锁屏媒体卡片：封面、歌名、播放暂停、上下首
- 四种播放模式由**一个按钮循环切换**：顺序播放 → 列表循环 → 单曲循环 → 随机播放（不拆成「随机开关 + 循环开关」两枚开关——那样能组合出「随机 + 单曲循环」这种自相矛盾的状态）
- 全屏播放页支持**上下滑动切歌**（可在设置里关闭）
- 迷你播放条常驻底部，点开进全屏
- **播放队列可重排**：队列页**长按任意一首，直接拖到想要的位置**（不是一格一格挪），松手生效；
  拖动中被拖行浮起、其余行让位并压暗，落点一目了然，拖到列表上下边缘会自动滚动
  （自动滚动的下边界按**看得见的底边**算，手指停在底栏上方就会开始滚，
  不必把它拖到底栏下面去；拖动全程列表自己的滚动是关掉的，行不会和手指错位）
  （菜单里的「上移 / 下移」也还在，两者改的是同一条队列）

### 曲库

- 扫描设备音频（MediaStore），另支持 SAF 导入外部文件
- **只扫描指定文件夹**：打开后不再读取整机媒体库，只扫你授权的那一个目录（连子目录一起），因此也就不再需要「音乐和音频」权限
- **自定义歌单**：新建 / 重命名 / 删除，任意曲目可加入；歌单内可上移下移调整顺序，**歌单顺序即播放顺序**
- **批量选择**：**长按任意一行**进入多选（已在多选态时长按 = 再勾/取消这一首），之后可批量 **加入歌单 / 从歌单移除 / 去掉封面 / 隐藏 / 嵌入标签**；
  顶部显示已选几首与全选，歌单视图下「加入歌单」自动换成「从这个歌单移除」
  - 多选态下按返回键只退出多选，不会顺手把播放页关掉、更不会直接退出 App
  - 汇报一定说清**没做成的部分**：选了 10 首只有 3 首是新的，会明确告诉你「原本就那样 7 首」
  - **去掉封面只删 App 这一层**（联网缓存的与相册自定义的），随后**退回文件里内嵌的那张**；
    想连内嵌封面一起换掉就用「嵌入标签 → 写入封面」，那是直接改文件
  - 选中项跟着视图走：切歌单、搜索收窄、批量操作后都会自动收敛，不会留下"看不见却还选着"的歌
- 搜索、按多种字段排序
- **隐藏曲目**：不想要的歌从列表里拿掉，可随时恢复
- **归档**：把曲目复制进 App 专属目录统一管理（副本到手后原曲自动让位，不会留空库）
- 编辑歌曲信息（歌名 / 歌手 / 专辑），改动只作用于 App 内视图，不动原文件

### 菜单与确认

针对单首歌的操作，点右侧 ⋮ 之后从**底部弹窗**展开，不再是贴边的一长串小下拉框：

- **按对象分组**（播放 / 歌单 / 封面与标签 / 歌曲信息 / 曲库管理），顶部先摆出这首歌的封面、歌名与歌手 —— 打开就知道自己在给谁操作
- 每一项**带一句说明**，把后果讲明白：「隐藏这首 → 设置页随时能恢复，文件不受影响」「归档到 App 库 → 原文件删了也不会丢」
- 会**丢东西**的动作（取消归档 / 移出列表）才标红，其余不标 —— 标红是一项承诺：做了就回不来
- 同一句文案不跨页面复用：曲库里的「移出列表」到队列里是「移出队列」，队列里也不再出现毫无意义的「下一首播放」
- 「清空播放队列」这种一颗图标就能把正在听的歌停掉的操作，一律先弹确认

### 歌词

支持多种来源：

| 来源 | 说明 |
| --- | --- |
| 内嵌时间戳歌词 | ID3v2 `SYLT` / `USLT`、FLAC `LYRICS`，带时间轴则精确同步 |
| 内嵌纯文本 | 无时间轴时按歌曲时长自动均分对齐 |
| 同名 `.lrc` | 音频旁边放同名歌词文件即可 |
| 手动导入 | 从文件选择器导入 `.lrc` |
| **网易云** | 按歌名 + 歌手搜索，可选官方翻译合成双语 |
| **LRCLIB** | 按歌名 + 歌手 + 时长签名匹配 |

- 两个联网来源都可以在设置里**分别开关**
- 当前歌词的来源可以在**设置 → 歌词 → 当前曲目歌词来源**里看到（含同步状态：精确同步 / 自动对齐）；点「联网获取歌词」选候选时，每一行也会标出是哪家给的
- 歌词可**写回音频文件标签**（ID3v2 / FLAC），换播放器也带着走
- 歌词副本管理：联网获取的歌词落在 App 内部，可查看 / 清理

### 嵌入标签（把 App 里的东西写进音频文件）

**四个入口，都不需要先长按进多选**：

| 入口 | 作用范围 |
| --- | --- |
| 某一行 ⋮ →「写入文件标签…」 | 这一首 |
| 播放页 → ⋮ →「写入文件标签…」 | 正在播放的这一首 |
| 右上角 ⋮ →「把标签写进音频文件…」 | 当前列表看得见的全部 |
| 长按进多选 → 底部「写进文件」 | 选中的那几首 |

三者弹的是同一个勾选框，可以勾选要写什么：

| 写什么 | 落到哪 |
| --- | --- |
| 歌词 | MP3 的 ID3v2 `USLT`、FLAC 的 Vorbis Comment `LYRICS` |
| 封面 | MP3 的 `APIC`、FLAC 的 `PICTURE` 块 |

- 音频数据**原样保留**，不转码、不重新压缩；只重写文件头部的标签区
- **只支持 MP3 与 FLAC**，M4A / Ogg / WAV 会明确告诉你"这个格式写不了"，而不是默默失败
- 改文件不可撤销，所以确认按钮要点两次（先「下一步」再「确认修改文件」）
- 写入时保留原标签里的其他帧（ReplayGain、多语言标题之类），已有歌词帧会被替换而不是叠加
- 汇报按「写成功 / 格式不支持 / 没写入权限 / 写失败 / 没有内容可写」分开说，
  不会只丢一句"已完成"让你以为全都进去了

### 专辑封面

三级来源，顺序固定：**App 缓存 → 文件内嵌封面 → 渐变占位图**

- **文件内嵌封面**：ID3v2 `APIC` / `PIC`、FLAC `PICTURE` 块，自己解析字节
  （缓存按字节存而不是按位图存，一首歌只解一次，滚动列表不会卡）
- App 这层没有（也没联网匹配上）时才走 **iTunes Search API**，命中即缓存
- 可配置：**搜索地区链**（默认 中国台湾 → 中国香港 → 美国，最多选 4 个）、**匹配评分下限**（20–170，默认 90）
- 打开「自定义获取地区」就**自动实测一遍各地区延迟**（单位 ms，每测一个刷新一个），
  也可以随时「重新测速」：连不上、超时或被接口限流时如实显示**无法连接**，不拿一个假数字糊弄。
  延迟是当下网络状况，只留在内存里、不落盘 —— 存下来只会让人对着过期的数字做决定
- 批量补封面时显示**确定式进度**：第 N / 总数 + 当前阶段（搜索候选 / 下载封面 / 写入缓存）+ 成功·无匹配·失败计数
- 「去掉封面」删的是 App 这一层，之后会退回文件内嵌的那张 —— 它的实现就是上面这条解析
- **重新解析内嵌封面**：在别的播放器或工具里换过封面图时，缓存里那份已经过期，
  不给一条显式重读的入口就只能靠重启 App。四处都能点 ——
  播放页 → ⋮ →「重新解析内嵌封面」（正在播的这首）、某一行 ⋮ → 同名项（单首）、
  多选底部的「重读内嵌封面」（选中那几首）、设置 →「专辑封面 → 重新解析内嵌封面」（整库）。
  整库那条扫完会告诉你**有几首真的带封面**，因为"扫完了"本身回答不了"换成功没有"

### KWM 音乐解密

酷我客户端的加密文件（`.kwm`）可以直接导入：App 在本地解密后按**原格式**归档进曲库，不重新编码。

设置页有「KWM 音乐解密」分组，说明解密原理、扫描位置与文件命名规则。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 语言 / UI | Kotlin，Jetpack Compose（Material 3） |
| 播放 | Media3 1.8.0（ExoPlayer + MediaSession） |
| 异步 | Kotlin Coroutines / Flow |
| 存储 | SharedPreferences（`Prefs`）+ 内部目录文件索引 |
| 标签解析 | 自研 ID3v2 / FLAC 解析器（`core/tags`），不引第三方标签库 |
| JSON | 自研极简解析器（`core/online/MiniJson`），不引 Gson/Moshi |
| 网络 | 标准 `HttpURLConnection` 封装（`SimpleHttp`），不引 OkHttp/Retrofit |
| 图标 | 全部手写 `ImageVector`，不引图标库 |
| 构建 | Gradle 8.9 + AGP 8.7.3，compileSdk 36 / minSdk 26 / targetSdk 36 |

依赖列表刻意保持极短——完整清单见 [`app/build.gradle.kts`](app/build.gradle.kts)，算上 Compose BOM 一共 15 条。

**没有任何原生代码**：工程里没有 C/C++，也没有任何自带的 `.so`（只保留 `abiFilters` 过滤依赖里带进来的那一个）。

### 关于签名

**仓库里不含任何密钥**。签名信息从下面两处按顺序读取：

1. 仓库根目录的 `keystore.properties`（已 gitignore，本地文件）
2. 环境变量 `MELODY_STORE_FILE` / `MELODY_STORE_PASSWORD` / `MELODY_KEY_ALIAS` / `MELODY_KEY_PASSWORD`

```properties
# keystore.properties
storeFile=keystore/melody.jks
storePassword=你的口令
keyAlias=你的别名
keyPassword=你的口令
```

**两处都没有也能构建**——只是产出未签名 APK，不会构建失败。想自己出包就用自己的密钥，别用别人的。

## 项目结构

```
app/src/main/java/com/melody/player/
├── MainActivity.kt          入口
├── MelodyApp.kt             Application，通知渠道等初始化
├── core/                    纯逻辑，无 Android UI 依赖（单测覆盖的主要区域）
│   ├── tags/                ID3v2 / FLAC 解析与写入、内嵌歌词提取
│   ├── kwm/                 KWM 容器解析与解密
│   ├── online/              网易云 / LRCLIB / iTunes 的 API 封装与匹配打分
│   ├── LrcParser.kt         LRC 解析与时间轴
│   ├── Playlists.kt         歌单的增删改排与按 key 解析
│   ├── BatchOps.kt          批量操作的分组与"没做成的必须说出来"的汇报
│   ├── AudioFiles.kt        「什么算音频文件 / 什么目录该跳过」
│   └── PlayMode.kt 等
├── data/                    仓储层：曲库扫描、归档、歌词、封面、偏好
├── playback/
│   └── PlaybackService.kt   MediaSessionService
└── ui/
    ├── MelodyRoot.kt        根骨架 + 全局布局
    ├── player/              PlayerViewModel 与界面状态
    ├── screens/             曲库 / 播放页 / 队列 / 设置
    ├── components/          封面、进度条、迷你条、弹窗等
    └── icons/               手写矢量图标
```

`core/` 与 `data/` 不依赖 Compose，逻辑可以在 JVM 单测里直接跑——目前 **305 条单测**，覆盖 LRC 解析、标签读写与封面帧的写入-读回 round-trip、KWM 解码、歌词匹配、封面匹配打分、歌单增删改排、批量操作分组汇报、限定文件夹的文件判定、曲库查询与隐藏/归档规则等。

## 数据与隐私

- **不收集、不上报任何数据**，没有统计 SDK、没有崩溃上报、没有账号体系
- 联网只发生在你**主动触发**时：获取歌词、获取封面、获取翻译
- 请求直接发往对应服务：网易云音乐、[LRCLIB](https://lrclib.net)、iTunes Search API
- 全库扫描、歌词、封面缓存都在本机，卸载即清除
- 需要的权限：读取音频（`READ_MEDIA_AUDIO`）、前台服务（播放）、通知
- 开启「只扫描指定文件夹」后不再需要 `READ_MEDIA_AUDIO`，只持有你授权的那一个目录的读取权

## 已知限制

- 只做了真机在用的两种 ABI（`arm64-v8a` / `armeabi-v7a`），x86 模拟器需要自行加 `abiFilters`
- 发版未开启代码混淆（`isMinifyEnabled = false`），便于排查问题
- 顺序播放在底层映射为 `REPEAT_MODE_ALL`——这是为了绕开「队列走到最后一首时系统撤掉下一首按钮」的坑，代价是顺序播放放完一圈会从头继续，与列表循环的差别只剩界面图标
- 歌单只存曲目 key，不存快照：文件被删或被移出 App 库后，歌单里那一项会直接消失（歌单页会提示有几首已不在曲库），不会留一条点不开的记录
- 「只扫描指定文件夹」依赖 SAF 目录树递归枚举，少量深度过深或提供器特殊的目录可能扫不全
- 未做平板 / 横屏专门适配
